# RetailIQ Data Dictionary

Source extracts (PRD §9). All files are UTF-8 CSV with headers, generated by
`scripts/generate_source_data.py` (deterministic, seed 42).

## sales.csv — daily sales transactions (line-item grain)
| Column | Type | Notes |
|---|---|---|
| transaction_id | string | business key, e.g. T1000000 |
| transaction_date | date (yyyy-MM-dd) | must be valid, not future |
| customer_id | string | FK → customers |
| product_id | string | FK → products |
| store_id | string | FK → stores |
| promotion_id | string | nullable, FK → promotions |
| quantity | int | must be > 0 |
| unit_price | decimal | must be ≥ 0 |
| discount | decimal | must be ≥ 0 and ≤ quantity×unit_price |

## returns.csv — product returns and refunds
| Column | Type | Notes |
|---|---|---|
| return_id | string | business key, e.g. R500000 |
| return_date | date | must be ≥ linked transaction_date |
| transaction_id | string | FK → sales |
| product_id / customer_id / store_id | string | FKs → masters |
| return_quantity | int | > 0 |
| return_reason | string | Defective, Wrong Size, Changed Mind, Damaged in Transit, Not as Described, Late Delivery |
| refund_amount | decimal | ≥ 0 |

## customers_oracle_extract.csv — Oracle CRM extract
customer_id (PK), name, gender, date_of_birth, email, phone, city, state,
customer_segment (Premium/Regular/Budget/New), registration_date.

## products_mysql_extract.csv — MySQL product master
product_id (PK), product_name, category, subcategory, brand, supplier_id (FK),
unit_cost, selling_price. 8 categories: Electronics, Apparel, Home & Kitchen,
Grocery, Beauty, Sports, Footwear, Toys.

## stores_mysql_extract.csv — MySQL store master
store_id (PK), store_name, store_type (Flagship/Standard/Express), city,
state, region (North/South/East/West), manager, opening_date.

## suppliers_mysql_extract.csv — MySQL supplier master
supplier_id (PK), supplier_name, supplier_region, supplier_rating (0–5).

## promotions_mysql_extract.csv — MySQL promotion master
promotion_id (PK), promotion_name, promotion_type, discount_percentage,
start_date, end_date, campaign_channel.

## Curated warehouse tables
See `redshift/ddl/`. Conventions:
- `dim_*`: descriptive dimensions, `DISTSTYLE ALL`
- `fact_sales`: one row per sold line item; measures `gross_sales`,
  `discount_amount`, `net_sales`, `cost_of_goods`, `profit`, `profit_margin`
- `fact_returns`: one row per return event
- Audit columns on facts: `source_file`, `processed_ts` (trace back to source)
- `dim_date.date_key` is `yyyyMMdd` integer; `is_festive_season` flags Oct–Nov

## Deliberate data-quality issues (demo answer key)
`data/raw/_injection_manifest.json` lists every injected bad row by category
(null keys, duplicates, orphan FKs, invalid numerics, future dates,
return-before-transaction). It is NOT read by the pipeline — compare it
against the DQ log after a run to prove the checks work.
